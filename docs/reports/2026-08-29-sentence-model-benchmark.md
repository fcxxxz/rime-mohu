# 2026-08-29 魔虎整句模型基准：八股文、万象与虎码

> 本报告基于固定的 20,000 句、四种输入码流和同一批原始候选输出生成。
> 末尾的数值表由 `research/lm_sentence_compare/report_results.py` 直接生成。

## 结论摘要

- 在本次自然码主线的端到端结果中，Tiger TCSKNM 的整句 Top-1 四档分别为 **52.88%、59.73%、83.56%、89.31%**，高于八股文；相对八股文的配对差为 **+10.79、+10.03、+5.63、+0.98 个百分点**。但这不能单独归因于 n-gram：Tiger 使用不同的 native lexicon/解码器，coverage 也更高。
- 万象 LTS 在纯双拼、少量辅助和每词一辅上高于八股文 **4.56、3.76、1.80 个百分点**；每字一辅低 **0.74 个百分点**。四个配对 bootstrap 区间均未跨过 0。
- 辅助码确实显著降低歧义：平均辅助密度为 0、18.66%、60.21%、100.00%；但句长仍是主要难点，所有模型的 15-24 字 Top-1 都低于 6-9 字。
- 各自探针记录的 P95 为 Tiger 约 **64-82 ms**、Rime 八股文/万象约 **6-7 ms**；两者测量边界不同，不能据此断言用户端谁更快。
- “Tiger”在本文只指当前仓库的原生 TCSKNM 三元 n-gram 解码。可选 Qwen 神经重排没有混入主结果。
- 在“两个模型都覆盖目标句”的条件子集上，Tiger 相对 BGW 的 Top-1 差为 **-16.06、-14.49、-8.58、-5.35 个百分点**（四种输入条件）。这是一个描述性、带选择偏差的条件统计，不能当作无偏的模型排序比较；它提醒我们 Tiger 的端到端优势很可能主要来自候选晶格/词库覆盖差异。要回答“同一候选晶格上谁的 n-gram 更强”，还需要共享候选晶格实验。

## 阅读口径

- **Top-1** 是输入完成后候选列表第一项与目标句完全相同的比例。
- **Top-5/10/20** 是目标句在最多 20 个候选中的排名命中率；`coverage` 是目标句是否进入候选池，不等于首选正确。
- **字符准确率** 是首选文本与目标文本的归一化编辑相似度，不能替代句级准确率。
- 主表的 Top-1 区间是 Wilson 95% 区间；相对八股文的区间是同一句配对、固定 seed `20260829`、10,000 次 bootstrap。报告末尾另列共同 coverage 子集的配对差。
- 每条输入在干净的临时 Rime 用户目录中独立评测，没有用户词频、候选置顶、候选调序或跨句提交历史。

## 实验设计

### 语料

- 新闻：CLUE TNews `train.json`，15 个领域，确定性分层抽样 10,000 句。
- 日常：Hugging Face `silver/lccc` 的 `lccc_base_test.jsonl.gz`，展平对话后确定性抽样 10,000 句。
- 统一转简体、去空白、只保留 6-24 个 CJK 字符，按文本去重。最终 ID 和文本均为 20,000 个唯一值。
- 语料原文及压缩源文件不提交仓库，许可证和来源哈希见配套 manifest。

### 输入码流

以 `pypinyin` 的整句读音消歧为基础，转换为自然码双拼。辅助键取 `mohu_zrm.chars.dict.yaml` 中由 Tiger 主码生成的辅助字段首键；多音字按字典权重和稳定规则选取。四个条件为：

1. `pure`：连续双拼，不加辅助。
2. `sparse`：每四个最大匹配词取一个词首，加一位辅助键（第 1、5、9… 个词）。
3. `word1`：每个最大匹配词的词首加一位辅助键。
4. `char1`：每个字符后加一位辅助键。

最大匹配词边界来自当前自然码普通词库和固顶词库，最长 10 字。平均辅助量分别是 0.00、2.12、7.00、11.76 个字符，占句长 0.00%、18.66%、60.21%、100.00%。有 7 条句子的 9 个字符读音未找到目标双拼条目，按固定字典首项回退；没有因此删句。

### 模型与运行时

- 八股文使用 `zh-hans-t-essay-bgw.gram`。
- 万象使用 `wanxiang-lts-zh-hans.gram`，参数为 `collocation_max_length=6`、`collocation_min_length=3`，以及 staging 脚本中的固定 penalty。
- BGW 与 WX 在同一 `mohu_zrm_sentence` 词库、棱镜、候选读取器和临时用户目录条件下只替换 grammar，便于观察模型差异；这不是两个完整发行包的端到端产品排名。
- Tiger 使用当前仓库的 native lexicon 和用户目录 `mohu_llm/data/` 下的 `sentence-ngram-mobile.bin`，由同一 native engine 解码；其候选晶格与 Rime grammar 路径并不相同。
- Rime 探针最多记录 20 个候选；每个 model/mode 都有 20,000 个输入行。Tiger 的空候选为 sparse 4、word1 6、char1 6，均已计入 coverage 分母。共同 coverage 配对表只比较双方都非空且目标在候选池中的句子。

### 完整性审计

已检查：四种模式各有 20,000 个唯一 raw；BGW/WX/Tiger 每个模式均有 20,000 个结果；Rime C/E 记录计数一致；Tiger data/latency raw 集合一致且无重复；所有结果行都能回连唯一句子 ID。原始 TSV、延迟文件和逐行 `results.jsonl` 保存在本地临时目录，不随仓库分发。

## 解读

1. **纯双拼**：端到端 Tiger 比八股文高 10.79 个百分点，比万象高 6.23 个百分点；万象比八股文高 4.56 个百分点。由于 Tiger 的候选晶格不同，这个差值同时包含词库覆盖、解码和模型排序影响。
2. **少量辅助**：只在每四个词的词首加一键，Tiger 仍比八股文高 10.03 个百分点；这说明少量消歧对三者都有帮助，但没有抹平模型差异。
3. **每词一辅**：Tiger 达到 83.56%，比八股文高 5.63 个百分点，万象为 79.72%。词边界信息带来的收益大于单纯增加候选数量。
4. **每字一辅**：三者都接近 88-89%；Tiger 以 89.31% 略高于八股文 88.33%，万象为 87.58%。此时输入信息已经很充分，模型差异被压缩。
5. **候选池与首选**：Tiger 的 Top-20/coverage 在四档分别为 79.31%、84.88%、97.71%、98.57%，远高于其 Top-1；实际使用中翻页或人工修正仍有价值。共同 coverage 表显示，条件化到双方都能提出目标句后，Tiger 的首选排序反而低于 BGW，这正是候选晶格差异的证据。
6. **领域与长度**：新闻和日常的总体趋势一致；Tiger 在多数新闻领域领先，但小样本 `news_stock`/`news_story` 的百分比不稳定。长句 15-24 字是共同短板，不能用短句成绩外推到长篇输入。

## 限制与不可外推项

- 本轮只测自然码双拼。仓库同时提供小鹤方案，但没有把同一 20,000 句再复制一套小鹤结果；因此本文不能回答自然码与小鹤之间的差异。
- BGW/WX 是在同一魔虎词库、棱镜和 Rime 探针上替换 grammar 的受控比较；它回答的是“模型替换后的排序差”，不是八股文发行包、万象发行包和魔虎发行包的完整产品排名。Tiger 使用另一套 native lexicon/解码器，因此 Tiger 与 BGW/WX 的端到端差值不能解释为纯语言模型增益。
- Tiger 端到端候选来自当前 native lexicon；空候选（4/6/6）不是被强行当作错误文本，而是保留为 coverage 缺失。字符级相似度也不能把空候选解释成部分正确。
- 关闭了用户词频、候选置顶/调序、跨句上下文、emoji、简繁转换和 Qwen 重排。因此结果更接近冷启动、单次整句输入，不代表长期使用后的个人词频体验。Rime 的计时包含候选遍历/输出，Tiger 的计时来自 native decode kernel；P50/P95 只能作各自运行成本参考，不能当作严格的用户端延迟对比。
- 语料是 TNews 新闻稿和 LCCC 对话的固定抽样，均限制为纯 CJK、6-24 字。它不覆盖数字、英文、标点混输，也不等同于 perplexity 或人工击键速度测试。
- 本次新增不提交下载语料、外部万象/Tiger n-gram 和逐行候选 dump；仓库已有的方案资源仍按各自文件许可管理。仓库只保留代码、汇总和哈希 manifest，复现时必须重新取得相同哈希的外部资源。

## 复现入口与产物

核心脚本位于 `research/lm_sentence_compare/`：

```bash
uv run python research/lm_sentence_compare/corpus/build_corpus.py
uv run python research/lm_sentence_compare/encode_sentences.py
uv run python research/lm_sentence_compare/prepare_staging.py
uv run python -m research.lm_sentence_compare.report_results \
  --cases research/lm_sentence_compare/cases.jsonl \
  --results /path/to/raw-results \
  --out /path/to/report \
  --artifact-manifest /path/to/manifest.json
```

Rime 原始探针需要 Squirrel 的 librime/lua/octagram 动态库；Tiger 原始探针需要当前仓库的 `libtigerengine.dylib`、native lexicon 和外部 n-gram。Tiger runner 默认校验 engine、n-gram、lexicon 的 SHA-256，并默认只接受 Top-20；如明确使用实验资源才可显式 `--allow-unpinned-resources`，且 run manifest 会记录 bypass 状态。所有运行参数、资源 SHA-256、原始输出文件名与完整性计数见 [`2026-08-29-sentence-model-benchmark.manifest.json`](2026-08-29-sentence-model-benchmark.manifest.json)。仓库内的 `.summary.json` 和 `.summary.csv` 是机器可读的同一份汇总；`results.jsonl` 和 16 个原始 TSV 只在本地临时目录保留。对已有 raw 结果重算时，应显式传入 `--artifact-manifest`，报告器会逐字节校验 16 个 raw/latency 文件；joined `results.jsonl` 是重算产物，不作为输入文件重复校验。
