# 四码字词基础顺序统一到主码表

## 规则与实现

原先 `mohu_zrm.dict.yaml` 中“芫 yjlm”在“演练 yjlm”前，但普通模式会读取独立避让表，将“演练”提前。现在普通四码输入有主表单字撞码时，单字与二字词直接按 table translator 的同码行序输出。三字以上四码简词保留 secondary 标记，紧跟首个基础候选；合并后单字出简让全可继续将它移动到最终首选之后。

没有主表单字撞码时，普通二字词仍按 smart 排序。主表别名缺词补出保留，包括“几乎 johu”；这条路径最多预取 20 个 smart 候选并重放同一查询，不再因为遇到避让表里的词而提前停止。该补出仍是有界前缀判断，不保证区分第 21 位以后出现的同文候选。词辅、短码、固词、native 解码、个人置顶与调序未作算法修改。

删除自然码/小鹤两份运行时避让表、加载器、生成器，以及旧门槛/豁免配置；打包不再携带这些资源。主码表没有改写，小鹤码表不作独立维护。历史词频研究数据保留，不参与四码碰撞排序。

`yidm` 的改变也来自主表行序：邑在一点和咦之前，邑没有对应前缀简码条目，咦仍按出简让全后移。独立规则退出后，其余撞码也会按主表重排，不能宣称所有其他首选不变。

在另一个测试副本中，只交换“芫 yjlm”与“演练 yjlm”两行，重新编译后实际菜单恢复“演练 → 芫”。这验证了码表行序能双向维护字词优先级。仓库主表和个人目录码表均未交换。

## 完整词的闪电标记修正

主表顺序接线后，固定候选仍用原有内部标记进入学习对象替换，重排滤镜将标记显示为闪电，因而 `金丹 jndj`、`演练 yjlm`、`禁区 jnqu` 等完整双拼词被误标成简词。

提示滤镜现在将完整词的裸闪电转换为非显示的 `mohu_table_full_word` 身份，保留原始 Phrase 为 genuine。实际鼠须管会在 Shadow 注释为空时继承底层注释，故须清掉底层误显示的裸标志，再以独立身份保护位置；不能仅靠空注释覆盖。后置语义门控识别这项身份，冻结码表位置。真实简词、实际短码提示和单字现有显示不变；空提示符不能把普通无注释词误认成码表词。

真实引擎在简码提示开/关两档验证：金丹、演练、禁区均无裸闪电；机难轻失保留闪电；进去在提示开启时保留 `⚡jq`。相同数据的 700 编码对照，候选文本与顺序逐条不变。35 个 Lua 测试全部通过，配置/小鹤资产测试通过。证据：`.tmp/full-code-hint/`。
