# 单一可见方案设计

## 目标

自然码包和小鹤包在 Rime 的“输入方案设定”中各只显示一个主方案：
`mohu_zrm` 或 `mohu_flypy`。字词、辅筛、整句、core、legacy、字符集和
反查词典等内部配置不再作为可选方案出现。

主方案中已经合并的整句、辅助码、简快码、词典学习、虎码反查和候选排序
能力保持不变。

## 根因

librime 的方案设置接口会非递归扫描用户目录和共享目录中的全部
`*.schema.yaml`。文件只要同时包含 `schema/schema_id` 和 `schema/name`，就会
进入可选方案列表；该接口不支持 `hidden` 字段。当前发布脚本会复制全部
`mohu_<scheme>*` 文件及公共工具方案，因此内部依赖也被展示。

## 发布结构

- 每个发布包只保留一个有名称的公开 schema：`mohu_<scheme>.schema.yaml`。
- 删除不再使用的完整独立方案，尤其是辅筛和 core 方案。
- 仍需触发 Rime 词典编译的依赖改成最小编译 schema：保留 `schema_id`、
  `version`、必要的顶层 `translator/dictionary` 和最小引擎配置，但不包含
  `schema/name`，因此不会进入方案设置列表。
- 主方案依赖只指向这些最小编译 schema；运行时配置继续全部位于主方案。
- 发布包加入无名称的旧 ID 覆盖文件，覆盖解压升级后可能残留的旧整句、
  辅筛和 LLM schema。旧 ID 不再提供可用输入方案。

## 兼容边界

不改用户词库命名空间和主方案 ID，因此现有调频、同步数据和自定义配置继续
使用原位置。发布包不能删除用户目录中的任意未知文件，只覆盖本项目明确发布过
的旧 schema 文件；用户自己的其他输入方案不受影响。

## 验证

- 分发测试模拟 librime 的扫描条件，断言每个包只有一个同时包含
  `schema_id` 和 `name` 的 schema。
- 断言辅筛、字词、整句等完整独立方案不进入发布包。
- 使用隔离 Rime 用户目录重新部署两个包，确认主方案及依赖词典编译成功。
- 运行现有 schema、分发和输入行为测试，确认主方案功能与候选行为不变。
