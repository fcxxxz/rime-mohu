# 自定义双拼/辅助码：构建你自己的魔虎方案

面向想换双拼布局或辅助码的用户。不用改任何仓库源文件——准备好一个或两个输入文件，
跑一条命令，得到一个可与官方魔虎·自然码/小鹤**共存**安装的完整方案（含原生整句引擎）。

```bash
# 换双拼（辅码保持虎码）
uv run tools/custom/build_custom_scheme.py --sp 我的布局.yaml
# 只换辅码（双拼保持自然码）：直接给辅码表
uv run tools/custom/build_custom_scheme.py --aux 我的辅码.tsv
# 只换辅码：扔一张形码全码表（五笔/仓颉/郑码/自编），按魔虎取位规则推导
uv run tools/custom/build_custom_scheme.py --shape-code 我的形码.tsv
# 组合 + 指定方案名 + 打包
uv run tools/custom/build_custom_scheme.py --sp 我的布局.yaml --shape-code 我的形码.tsv --name myscheme --zip
```

产物：`custom-dist/mohu_<name>/`（可直接放进 Rime 用户目录）+ `构建报告.txt`。
需要 Python 环境（仓库根目录执行，依赖 uv，见 README）。

内置布局预设：`zrm`（自然码）、`flypy`（小鹤）、`jiajia`（拼音加加）——
`--sp` 直接传名字即可；其余布局自己写文件。

## 输入文件一：双拼布局（YAML）

格式与逐项注释见样板 [tools/custom/examples/小鹤双拼.yaml](../tools/custom/examples/小鹤双拼.yaml)，
要点只有三条：

```yaml
name: myscheme     # 方案 id：小写字母开头、仅小写字母数字；产物叫 mohu_myscheme
display: 我的方案   # 选单里显示「魔虎·我的方案」
initials:          # 声母：与拼音同形的不写，只写 zh/ch/sh
  zh: v
  ch: i
  sh: u
finals:            # 韵母→键：一行一个韵母，约 35 行
  ang: h
  uan: r
zero:              # 零声母音节（a/o/e 开头）整音节打法，约 12 项
  a: aa
  ang: ah
```

工具在全部 414 个合法音节上展开并校验：漏韵母、编码不是两字母、两个音节撞同一个键，
都会用中文报错指明位置；**反查映射由枚举自动推出，不需要写任何逆规则**。

已知限制：布局必须只使用 a–z 键。微软双拼/搜狗双拼把 ing 放在分号键上，
与魔虎辅码体系的 `;` 分隔符冲突，无法表达——这类方案请改用别的近似布局或自行微调键位。

## 输入文件二a：辅码表（`--aux`）

格式见 [tools/custom/examples/aux.sample.tsv](../tools/custom/examples/aux.sample.tsv)：
`字<Tab>正常辅码<Tab>[14位]<Tab>[13位]`，辅码 1–2 个小写字母。
**只列要改的字**，没列的保持虎码辅码；构建报告会列出覆盖统计。
缺字默认回退虎码，`--strict` 改为缺字报错。想整体替换辅码：

```bash
uv run tools/custom/build_custom_scheme.py --emit-aux-template   # 导出 83,975 行虎码全量模板
# 改完后
uv run tools/custom/build_custom_scheme.py --aux aux-template.tsv
```

## 输入文件二b：形码全码表（`--shape-code`）

只会背形码、没有现成辅码表？直接扔全码表（格式见
[tools/custom/examples/shape-code.sample.tsv](../tools/custom/examples/shape-code.sample.tsv)：
`字<Tab>完整编码[<Tab>根数]`，编码 2–6 个小写字母）。工具按魔虎对虎码的同一套取位规则推导：

| 规则 | 内容 |
|---|---|
| 选主码 | 按源序取第一个四码；没有四码则取最长码的第一个。其余编码列入报告当别名候选 |
| 正常辅码 | 主码第 1–2 位 |
| 14 位兼容 | 主码第 1+4 位（主码 ≥4 位时） |
| 13 位兼容 | 主码第 1+3 位（主码 ≥3 位时） |
| 剪枝 | 默认不剪——通用形码（五笔/仓颉/郑码）每个码位都是字根，12/13/14 全合法。大小码体系（虎码家族）才提供根数列或加 `--tiger-style-prune` |

推导出的辅码表会落盘到产物目录（`推导辅码表.tsv`），可以检查微调后再当 `--aux` 传入。

## 简快码是自动的，不用配置

- 三码（双拼+首辅）、全码（双拼+双辅）、全码后缀 `o`/`/`、词末辅码接续——部署时由拼写运算从烘入的辅码自动派生；
- 13/14 位兼容打法——自动以低权重注入；
- 一简/二简等声母简码——从自然码主码表转换带入（声母与拼音同形，各双拼通用）。

## 构建报告怎么读

- **辅码覆盖**：你覆盖了多少字、多少字回退虎码（样例字列表）。
- **辅码离散度**：你的辅码当「消歧器」好不好用——「全码」列的「单字独占」比例越高越好
  （虎码基准约 91%）；最挤的码位列出了值得用兼容位或别名分散的热点。
- **主码表转换 / 词库源转换**：无法转换的无理码与拉丁字母词条（原样保留，不影响使用）。
- **自检**：schema 引用、词表命名、包契约的自动检查，应全部通过。

## 安装（与官方魔虎共存）

1. 把 `custom-dist/mohu_<name>/` 内**全部内容**合并复制到 Rime 用户目录
   （macOS `~/Library/Rime/`）。包里没有 `default.yaml`，不会覆盖你现有的方案列表。
2. 按包内 `default.custom.yaml` 的写法把方案加进列表（已有该文件时并入 patch 段）。
3. 整句模型：已装官方魔虎的用户直接复用 `mohu/model/`；新装用户从 Releases 下载
   `mohu-sentence-ngram-v5.bin` 放入。
4. macOS 双击 `解除隔离.command`，重新部署后在方案列表选择「魔虎·你的方案」。

你的用户词库（`*.userdb`）、候选调频与其他魔虎方案互不影响；本方案的辅码提示表
（`lua/zrmdb_<name>.txt`）按方案独立，不会覆盖共享的虎码表。

## 已知降级（预期行为，不是 bug）

- 无飞键别名（自然码/小鹤的飞键是针对各自音系调的，不迁移）；
- 四码字词让位调优为空、简码人工调序不迁移（这些是自然码主表上的调优数据）；
- 拆字提示（chaifen）与虎码反查仍显示虎码数据——换了辅码的话，这两处展示的仍是虎码；
- 主表中与自然码绑定的无理码（如 `默认 mry`、o 引导符号区的个别行）原样保留。

## 常见问题

- **构建报「同码异音节碰撞」**：你的布局把两个不同读音折到了同一个键组合，无法反查。
  报错里列出了冲突对，调整对应韵母的键位。
- **构建报「缺少韵母 X」**：键位表漏写了韵母 X；抄键位图时 üe 记得 ve、ue 各写一行。
- **换了辅码后辅助码提示显示的不对**：提示表已按你的方案生成（`lua/zrmdb_<name>.txt`）；
  拆字提示展示的是虎码拆分，与你的辅码体系无关，可关掉 chaifen 开关。
- **能用大牛/智能ABC/星空键道 吗**：只要键位在 a–z 内、且每个读音有唯一两码组合，
  写成布局文件就能用；分号键方案（微软/搜狗）不行。
- **构建很慢？** 全量管线要处理两百万词级数据，首次约 1–2 分钟属正常；
  产物在 `custom-dist/`，重复构建会重建同目录。
