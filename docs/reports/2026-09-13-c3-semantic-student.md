# C3 语义学生 v1：训练、评测与门槛判定（2026-09-13）

按训练合同 C3 replan（qwen-semantic-reranker-training.md）在本地 Mac 完成
P0–P5 全流程。本文记录实施细节、结果与门槛判定。

## 实施（相对计划的偏差已标注）

- **数据（P0）**：词形态 993,919 菜单（build_dataset.py 在 **w=1.5** 引擎上
  重放，词对冲突类自然入集）＋整句形态 104,765（build_sentence_dataset.py，
  context=真实前句、候选=整句，新增）＋ adv-eval 1,612（19,996 句网格翻转，
  与训练语料 0 重叠）。全部经 add_context_scores.py 补**部署同源**的
  V5 上下文字符分（tiger_engine_context_char_scores），消除训练/部署特征
  尺度错配。
- **老师（P1，偏差）**：Qwen 软标签蒸馏降级为 v2 备选——w=1.5 捕获已含
  对抗类真值标签，先验证 CE 上限。
- **训练（P2，偏差）**：41.6M（512/6/4/2）在 MPS 上步速不达标，重训为
  **18.7M（384/4/3/2）**；数据取全错误 139,510＋1:1 哈希采样正确
  139,143＋全句形态 104,765 ≈ 38 万，2 epoch、batch 64、~50 分钟
  （train_pipeline.py 原配方，CE＋preserve 加权）。
- **导出（P3）**：fp32 71MB（p50 16.7ms/p95 21.3ms，manifest 基准）；
  int8 动态量化无收益（单线程 transformer 常态），保留 fp32。
  `make tigerengine-semantic`（真实模型方向性/释放测试）通过。
- **评测器**：eval_c3_policy.py 逐条复刻 lua 过滤器策略（含**首位钉住
  margin 保护**——初版评测器漏了这层导致 C3 修反虚高，已修正并对 C2
  基线同步重测）。

## 结果（全部同集同策略对拍）

| 评测集 | C2（现役） | C3 v1 |
|---|---|---|
| tnews 词测试 58,539（门开 4,209） | +0.28%（196/34，5.8:1） | **+0.88%（578/62，9.3:1）**；门开子集 61.9%→74.2% |
| rmrb 词 dev 89,636 | — | +0.86%（889/116，7.7:1） |
| tnews 句测试 7,895 | 0.00% | 0.00%/−0.08%（中性无害） |
| adv-eval 1,612（网格翻转，混合形态） | +0.06% | −1.18%（回退子集救回 12.8%＝C2 的 4 倍，但修复子集破 36 个） |
| margin 扫描（词测试） | — | 0.15:+0.88%/9.3:1；0.3:+0.79%/**26.7:1**；0.5:+0.69%/203:1 |
| 延迟 | ~12.5/66.9ms | 16.7/21.3ms（p95 更优，p50 超 15ms 预算 2ms） |

C-ABI 抽查：词形态下 C2 与 C3 都判对（支持>只吃）——C2 当年的失败是
**句子候选 OOD**（整句形态 C3 也未解决：浙商/这伤心、县委/现为中心组
这类实体替换需要老师级知识）。

## 门槛判定（对照预注册门槛）

- L2 双侧净效应：词形态 **+0.88%**，未达预注册的 +1pp（差 0.12pp）；
  修好:修反 9.3:1 ≥ 3:1 ✓。
- L1 对抗救回 ≥ 老师 70%：**未达**（门开回退救回 12.8%，老师同协议 58%）；
  adv-eval 净 −1.18%（该集为训练外混合形态，C3 在此 OOD）。
- 结论：**C3 v1 是明确的「更好的 C2」（词形态净效应 2.8 倍、保护比 1.6
  倍、p95 减半），但不是对抗类的解**。按 P5 纪律未自动替换发行模型；
  工件与全部评测在案，替换=复制两个文件（mohu_semantic.onnx/vocab.tsv），
  回滚同样是一个文件复制。

## 遗产（复用资产）

## v2 方向（按证据优先级）

0. **门关子集的老师上限实测（2026-09-13 补充）**：把 227 例门关回退
   强制喂给 Qwen3.5-0.8B（同协议），救回 132（**58%**）——与门开子集
   （148/254，58%）完全一致。**门没有挡住更难的题，对好模型是纯粹
   阻塞**；483 例全开门口径老师可救 280（58%）。这把「词证据分歧门」
   的预期收益从推测变成实测：门扩展 + 老师级质量 = 58% 可达。
1. **老师 KL 蒸馏**（Qwen3.5-0.8B 软标签打标错误菜单子集）：词形态已到
   CE 上限附近（救不动的 61.9%→74.2% 之外的硬核是实体/搭配知识），
   老师在同类题上 52–58% 的上限值得蒸馏；train.py 已有 teacher 接口。
   学生逼近老师的程度（蒸馏损耗）是 58% 目标的真正瓶颈：v1 学生在
   门开集上 12.8% vs 老师 58%。
2. **词证据分歧门**：47% 回退 case 死于门关——上表实测它们可救率与
   门开集相同，门扩展无质量代价。词边先验的分叉信号（top1 不用词典
   词而 top2 用）作为开门条件，与词形态重排能力正交叠加。
3. 整句形态实体替换：18.7M 学生容量不足以承载（本轮实测中性）。
   要一次性拿满 58% 的替代路径是**老师直接上岗**（停顿后异步重排，
   青简形态）：技术今天可行（本机 MLX 0.8B，~100ms 级），卡点在产品
   形态（外部辅助进程曾因 librime-lua 无 luasocket + 需用户自启被否），
   属产品决策非技术决策。
