# V5 加“现在”后整句变整剧：逐项稳定性调查

日期：2026-10-09。问题：`vgxjuvijxwudi` 首选“整句直接无敌”，
`xmzlvgxjuvijxwudi` 首选“现在整剧直接无敌”。用户希望无关前缀不破坏
已经可正确识别的词，要求调查而非继续更换模型。

## 范围与可复现证据

全程用本机默认 V5 字符模型：
`~/Library/Rime/mohu/model/mohu-sentence-ngram-v5.bin`；词表为
`~/Library/Rime/mohu/data/zrm/mohu_zrm.lexicon.txt`。
独立 C++ 探针直接包含当前源码，读取模型和词表、输出 beam 路径及每字分数。
不载入个人 snapshot 或用户词条；不修改生产源码、模型、码表或用户目录。
探针和输出为 `.tmp/long-context/v5-prefix-audit.cc` / `v5-prefix-audit.txt`。
真实菜单探针运行于备份副本 `/tmp/mohu-runtime-check.5HOG3N`。

运行参数与本机一致：beam 200、reading prior 1、composed prior 1.3、
word edge 0.5、text lexicon / word form 6.5、learning context guard 开。

| 对照 | 结果 | 能排除什么 |
|---|---|---|
| 不载入个人模型/个人词，完整重算 | 无前缀整句；加现在整剧 | 个人学习不是复现的必要条件 |
| 所测前缀逐键追加 vs 每一步完整重算 | 输出逐字节一致 | 本次翻转不是增量缓存偏差 |
| beam 100 / 200 / 500 | 原两条输入首选相同 | 在该范围内不是 beam 太窄造成 |
| word edge 0 / 0.5 / 1 / 1.5 | 无前缀整句；加现在整剧 | 调大现有词边奖励不能补缺失词边 |
| 真实菜单 contextual_order 关 / 开 | 一次性整句输入都同样翻转 | 跨上屏候选重排开关不是直接原因 |
| 先提交“现在”，关 contextual_order，再打后半句 | 整句直接无敌 | 不能混淆已提交历史和同一 composition 前缀 |

这不是“同样输入有时随机变”。本轮同条件输出确定，变化由不同输入的局部
条件概率引起；用户观察到的是对无关前缀过敏的排序稳定性问题。

## 翻转分差逐项闭合

只比较整句/整剧，数值越大越优。以下为候选输出中的最佳路径分，不是
logsumexp 的路径质量；这两文本其他路径的增量结构相同，实际菜单同序。

| 比较项 | 无前缀 | 加现在 |
|---|---:|---:|
| 整句候选路径分 | -23.046417123 | -27.039637287 |
| 整剧候选路径分 | -24.628833028 | -26.482630526 |
| 句相对剧的最终优势 | +1.582415905 | -0.557006761 |
| ju 位置的字符条件 logP(句) | -7.173505671 | -10.407178146 |
| ju 位置的字符条件 logP(剧) | -8.544910202 | -9.639160012 |
| ju 位置句相对剧的优势 | +1.371404531 | -0.768018134 |

句相对剧的优势减少 **2.139422666**，与最终路径优势减少量相等（舍入误差内）。
后续“直接”对两候选的相对贡献、共享“无敌”、EOS 均没有因添加前缀而改变。
翻转的直接原因因此集中在 `ju` 的局部条件变化：

```text
无前缀：P(句或剧 | <句首>, 整)
加现在：P(句或剧 | 在, 整)
```

模型里“在整→句”的直接三元记录不存在，打分走回退；“在整→剧”有直接
记录（direct probability 0.000056995）。这只能证明编译模型的统计证据不同，
不能证明真实语料把“在整”标成一个词，也不能凭这个记录判定语义正确。

## “现在”没有被拆，但完整词边不等于字符窗口有词界

两条加前缀候选的最佳路径为：

```text
[现在] [整] [句] [直接] [无敌]
[现在] [整] [剧] [直接] [无敌]
```

“现在”使用 `xmzl` 的完整词边，已完整参与解码。V5 字符分支仍对该词的
每个字逐个更新 `prev2/prev1`；读到整后，上下文自然变为在、整。
此前把问题归结为“现在被切成在整”不准确：**在整是评分窗口，不是分词结果**。
即使允许一个完整的整句词边，沿用现有字符累加公式，也仍会计算
`P(句 | 在, 整)`，除非另外融合词证据或改进模型。仅把两个字改为两个词的
界面参数，不会自动让已有字符模型学会对应的词转移概率。

## 更具体的实现缺口：辅码输入丢失整词身份

生产词表有 `vgju -> 整句`（rank 2，weight 267），没有 `vgxju -> 整句`。
单字 `vgx` 同时对应争/整，辅码本身并非唯一识别整。
当前扩展循环按原始字符串 `raw.substr(...)` 精确查 `lex.codes`，不会将
合法带辅的字边组合映射回原词的规范双拼键。输入 `vgxju` 因此只能走
整+句的字符边；不会自动获得 `vgju` 的完整词证据。

这使本来已在词典里的“整句”，在带辅长句里与无码表词“整剧”的拼装路径
竞争时缺少一票。直接修改词频或全局词边权重无效，因为这条词边根本没有
进入候选图；提高已有其他词边的权重对两路径相同。

## 离线补词边试验及其局限

仅在探针内存中，将词表已有的“整句”条目临时挂到 `vgxju`；不写源码、
不加码表行、不改变用户目录。现有 V5、word edge 0.5 下：

- 无前缀仍是整句。
- 加现在的整句分 -26.4772450，整剧分 -26.4826305，整句领先约 0.0053855。
- 临时词边沿用原词 rank 2，代替了字符组合中句的 rank 8；若把临时词边
  rank 固定为 8，word edge 0.5 下整剧仍第一。
- 固定 rank 8、word edge 0.75 时整句第一，但不能据此推荐全局改成 0.75。
  其他候选共有词边也受其影响，本轮没有完成整套回归或性能验收。

这说明补回词身份能提供正确方向的证据，却没有证实一个稳定、通用的修复。
尤其不能把一个“领先 0.005”的偶然翻转当作部署成功。

## 推荐修复方向与验收要求

先修**带辅码的词身份保留**，再测**局部词证据和字符分的融合**。
保持 V5 候选生成基础、保留所有合法字符回退，避免旧词模型整体替换。

1. 将实际字边的规范音节与辅码约束保留下来，在词典规范编码上识别可组成
   的完整词；验证每个字确实符合输入辅码。不能粗暴删奇数位，也不能只按
   汉字文本查词，否则会将 `ju` 的车错误接到整车 `vgie` 上。
2. 已确认的完整词在带辅输入下应获得与对应普通词码一致的词身份证据。
   别把派生兼容路径随意算成另一个码表档位，更不能重复计数同一词证据。
3. 对局部词候选的分歧比较词证据，控制它的贡献、避免长句按词数无限累加；
   是否需要调整融合规则，要由多个真实输入和反例测量决定。
4. “上下文可改变词选择”仍需保留：语境有实际区分力时应能改选。
   目标是无关前缀不过度压过可信词证据，不能冻结所有同音候选或切词时
   一律清空历史。

验收至少包含：原两句、多个正确编码的中性前缀；带辅/不带辅的词证据
一致性；争/整共享辅码；句/剧同音；车 jū/chē 的合法与不合法组合；
“编辑”提交后码表；一次性编辑码表；费尽/费劲；个人词和缺词字符回退；
增量/完整一致性；长句基准与逐键延迟。

本轮调查没有部署新规则。上一轮词模式修复仍在工作区；本机运行的是其
重编库加原 V5，词模式不会启用。新的修复方向比“换两个词窗口”更具体，
但仍需要实现与回归，不能宣称原句问题已解决。
