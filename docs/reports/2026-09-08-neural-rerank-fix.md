# 神经重排：真实候选集、用户层与完整管线修复

日期：2026-09-08。目标方案：`mohu_zrm`，macOS Squirrel。

## 复现与根因

将实际部署的 build、Lua、运行库、码表及用户三元快照复制到隔离目录，使用
Squirrel 自带 librime 的 C API 逐键输入 `wlpo`、空格，再输入 `jwgzle`。
严格检查上屏文本为「外婆」，随后读取最终菜单，不直接注入上下文或候选。

修复前，最终菜单为「家给了、嫁给了、家给乐、家给勒、家给垃」。
对同一次调用记录的 Lua 输入、评分、输出和菜单进行对照后，确认
Lua 已按收到的分数排序，后续 filter 没有把本例的首选改回去。

1. **门控混入用户层。** 实际 20 候选中，纯静态 V5 的前五名 z-margin
   为 `0.650555`，低于配置的 `0.7`；读取现场用户快照后变为 `1.310579`，
   神经推理没有触发。反复测试、上屏过的错误词可能提高旧门控的置信度。
2. **等权相加并非接管。** 旧单测使用「家给了、嫁给了、加给了、假给了、夹给了」
   五个手选候选，而真实前五个是「家给了、嫁给了、家给乐、家给勒、夹给了」。
   归一化统计量不同。即使强制门控，旧公式 `v5_z + weight * neural_z`
   在 weight 上限为 1 时仍让「家给了」领先：无用户层 `2.573 > 2.179`，
   带现场用户层 `2.778 > 1.724`。
3. **只融合前五项。** 旧代码给整个批次做了神经推理，却只把前五项的神经分
   加入结果，第六项以后被当成神经分 0，无法一致评价完整候选批次。

这些数值来自同一批次的直接 C ABI 对照，而非旧调试标记文件是否存在。
独立推理成功不能替代实际候选集上的完整管线验收。

## 修复契约

- 门控只使用**静态模型**（保留静态模型混合，不含个人三元层），计算按输入顺序
  取前五个**不同文本**的 z-margin。同文 native/smart 副本不作为两个竞争答案；
  不去掉实际候选对象，不改变它们的输出槽位。
- 神经融合改为 `(1 - weight) * personalized_v5_z + weight * neural_z`。
  weight 仍限制在 `[0,1]`：0 完全旁路，1 在门控通过时使用神经排序。
  **这与旧实验版本的加法权重含义不同**，不能直接套用旧参数的离线数字。
  所有本批参与候选均使用自己的神经分；归一化参考同一组去重的前五个文本。
- 推理在当前评分请求内同步完成；移除没有任务生产者的遗留后台线程/缓存。
  不依赖下一键刷新，也不改 decode 的搜索逻辑。
- 新增 `tiger_engine_context_char_scores_ex(..., int* neural_applied)`。
  每次请求开始清零，成功融合后置一；旧 C ABI 保留，数值与扩展接口一致。
  Lua 的评分表携带布尔字段 `neural_reranked`，不影响数组长度。
- native 候选仅在配置了神经模型且使用 char 信号时参与探测；只有本次
  `neural_reranked == true` 才能移动。门控未开时恢复普通候选原有重排窗口。
  标点、固顶、简码、单字的稳定边界不变；显式候选覆盖仍在下游优先生效。
- 源码 Lua 桥接补齐神经配置、相对路径解析和配置签名。模型加载失败记录错误，
  V5 保持可用；旧库没有新布尔字段时 native 保持原位。
- 移除每次输入向 `/tmp/char_scores_called` 写候选的遗留调试代码。
- 本批存在空文本、词表外字符或会被神经编码器截断的候选时，整批保持基础分，
  `neural_applied=0`。不能把全 OOV 的默认零分或跳过部分字后的短串分当作有效高分。

本机继续使用既有配置，无需修改或清空用户数据：

```yaml
tiger:
  neural_rerank_model: mohu/neural_v3.bin
  neural_rerank_weight: 1.0
  neural_rerank_margin: 0.7
  word_order_rank_penalty: 0.0
```

词表与模型同目录，文件名为 `neural_vocab.json`。本例使用的原绝对模型路径也有效。
这里的 penalty=0 是本机已有实验设置，不修改两个发布 schema 的默认值。

## 回归与复现

原生回归使用真实 V5/神经模型，并在**内存中**学习「外婆家给了」150 次，
不读取或修改实际用户快照。旧实现出现 14 项失败，修复后通过；后补的同文重复
门控测试也经历两项行为失败后转绿。覆盖真实 20 候选接管、第五项以后候选、
用户层门控污染、去重门控、weight/margin 为 0 时字节级回退、扩展 ABI 标志与
非有限配置参数。模型缺失会明确 skip，不能把 skip 当作模型行为已通过。

```sh
make tigerengine-neural-rerank
lua tests/mohu_word_order_filter_test.lua
```

可通过 `TIGER_NGRAM`、`TIGER_LEXICON`、`TIGER_NEURAL_MODEL`、
`TIGER_NEURAL_VOCAB` 指定四项原生测试资产。

完整管线驱动是独立标准库脚本，不依赖原 `/tmp/mohu-tiny-bench` 模块：

```sh
python3 tests/neural_rerank_session_test.py \
  --user-data-dir /tmp/mohu-neural-debug-20260908 --repeat 3
```

必须先准备包含完整已编译数据和修复运行时的隔离目录；脚本拒绝直接操作
`~/Library/Rime`。初始化、提交和会话释放会写隔离目录的用户数据库。
它验证真实提交、最终菜单和期望首选，输出 JSON；可以通过
`--contextual-order off --expected-first 家给了` 检查开关回退。

- 本轮没有重跑五方案大语料基准，不声称整体准确率提升或给出总体修坏率。
