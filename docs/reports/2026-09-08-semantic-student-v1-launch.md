## 结论先行（2026-09-09 二次修正口径）

> **2026-09-09 数据唯一性补充审计：** tnews test 的 58,305 行只有
> 53,173 个唯一 `case_id`，5,132 行（8.8%）是内容完全相同的重复记录。
> 旧 top1 可解释为原始行加权数，但旧配对 bootstrap CI 把重复行误当独立
> 样本，**置信区间作废**。生产管线的 tnews 评测已改用 53,173 个唯一案例；
> 新 CI 只会在去重后的 production-menu 数据上计算。train/dev/probe 与
> 生产 probe 配对记录经复核均无重复。

**本报告全部数字的对照基线是「裸 V5 解码器输出顺序」，不是生产魔虎
菜单顺序。** 用户复核指出两个关键事实：(1) 值值案例「yuyt 鱼书雁帖→
预约」中，鱼书雁帖是 `mohu_zrm_fixed` 四码码表词（简码位次选），生产
express translator 的让位规则本来就先把 smart「预约」排前——裸解码
把码表词排第 1 的现象在生产管线中不存在；(2) 多音字字级路径（纤
qian/xian 两读）使非同音词进入候选，词级读音上它们不是竞争者。

因此：
- 「+8.0/+8.2pp vs native」是对**裸解码顺序**的修正量，不是对真实魔虎
  菜单的增益；生产基线（fixed/smart 交错 + 让位 + IJRQ + 简码位次）
  比裸解码强得多，学生的真实净增益未知，必须以隔离全管线回放重测。
- 学生已证明的能力：在裸解码分布上以真值监督学到上下文判别（与
  Qwen 零样本打分的对照仍在同批记录上有效）；其生产价值预计集中在
  「管线自身未消歧的真歧义菜单」——即门控 filter 的目标场景。
- 后续质量结论以「全管线回放（含 express translator 排序）」为准；
  本报告的 native-replay 数字降级为**解码器层消融记录**。

## 实验性语义门控 filter（2026-09-09）

- `lua/mohu_semantic_gate_filter.lua`（默认关闭，未接线）：复用字级
  student_gate 的骨架（luasocket 行协议、V5 歧义门控、硬超时、LRU 缓存、
  受保护槽位排除），按契约差异实现——独立开关、窗口全量 provenance
  强制（任一候选解析不出谱系整菜单直通）、首选翻转需语义 z 分
  margin（默认 0.15）。服务端 `scorer_service.py` 增加同构的
  `mohu-semantic-gate/v1` 行协议端点（实测通过；v1 JSON 评测协议不变）。
- 测试 `tests/mohu_semantic_gate_filter_test.lua` 8/8 通过：默认关闭、
  上文缺失、无谱系、socket 失败、畸形响应全部逐字节直通；窗口重排、
  margin 抑制、缓存命中行为正确。
- **已确认的既有 bug（未改动，待用户决定）**：实验性
  `mohu_student_gate_filter.lua` 的回填公式
  `ordered[slots[active[i].pos]] = block[slots[i]]` 方向反置——最小复现
  （学生分 甲=1/乙=5/丙=3）原式输出「丙,甲,乙」，即学生分的**精确倒序**
  （正确为「乙,丙,甲」）。语义 filter 使用修正方向
  `ordered[slots[i]] = block[slots[active[i].pos]]`。该 filter 默认关闭且
  未接线，但若实验启用会把学生最差候选顶到首位。

### native_score 特征依赖与 SCORE2 协议修复（2026-09-09）

- 消融测量：把 native_score 特征置零/常数，学生 top1 从 0.9462 崩至
  0.2307/0.0867——模型把 native decode 分数作为承重特征，语义信号在其
  上做保守修正（这正是低修坏 profile 的来源，也解释了对 Qwen 的净胜）。
- 因此 gate 行协议升级为 **SCORE2**：请求携带每个窗口候选的
  provenance native_score（`SCORE2\t上文\tK\t分数×K\t候选×K`），服务端
  按训练统计 z 归一；谱系缺分数的候选使整菜单 fail-open。旧 SCORE
  （常数分数）仅保留为兼容探测路径。
- 端到端验证（易烊千玺案例）：真实分数下目标以 3.9 分领先，常数分数
  下仅 0.4 近平局——margin 门控恢复判别力。filter 测试扩至 9/9
  （新增缺分数谱系 fail-open 用例）。
- 部署含义：语义路径只在「窗口全部候选均有同次解码分数」的菜单上
  生效（当前即 native 解码主导的整句输入场景），fixed/smart 主导的
  菜单自动保持原序——与训练分布严格一致。

- 全量 test：KL top1 **0.9440** vs 基线 0.9466（修正 5307 vs 5475）——
  20% teacher 覆盖下 KL 不及基线，按契约不推进该变体。

### 全覆盖 KL 复测（993,112 标签，2026-09-09 收官）

- 同 seed 同数据 3 epochs，teacher 标签 100% 覆盖。
- dev 0.9530（41.8M 系列最佳），但全量 test **0.9444** vs 基线 0.9466
  （修正 5338/修坏 799）——仍不及基线，dev 优势未泛化。
- **结论：语料真值监督强于 Qwen3-0.6B teacher 软分布，任何覆盖率下
  KL 蒸馏都不推进。** 实验矩阵就此收口：
