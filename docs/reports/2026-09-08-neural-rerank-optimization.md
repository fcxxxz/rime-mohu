# 神经重排：共享前缀、向量算子与上下文窗口

日期：2026-09-08。设备：Apple M1 Max。范围：实现并隔离验证，不部署线上运行库，
不切换输入源，不重启 Squirrel，不修改用户学习数据或生成词典。

## 实现

1. `neural_kernels.h` 使用 Accelerate 向量化 tanh-GELU 与稳定的全词表
   logsumexp。保持原 tanh 近似公式和 float 返回约定，指数和采用 double 累加。
   不使用 fast-math，不截断词表，不改成候选集合内 softmax。
2. `neural_infer.h` 对实际输入 token 前缀建 trie；同一层中，每个节点的
   Transformer/QKV 只计算一次，注意力仅能访问自己的祖先及自身，位置编码按
   路径深度索引。候选末字仍作为预测目标，但不再计算其无用的输入隐藏状态。
   输出头按唯一预测节点投影一次，再把各目标字分数回填到原候选、原字序累加。
3. 256 节点以内使用批量矩阵乘法和祖先掩码；更大树使用有界的逐路径注意力，
   不分配随整树节点数平方增长的注意力矩阵。输出头保留原 16MiB 分块。
4. 新增 `tiger/neural_rerank_context_chars`，通过 Lua、C ABI 到 scorer，支持
   `0–160` 码点，默认仍为 `160`。先截取最近一条上屏记录的尾部，再过滤 OOV。
   配置进入引擎缓存签名；旧库缺接口时明确记录非默认窗口无法生效。
5. 不改门控、20 候选覆盖、用户层权重、候选有效性整批回退、neural_applied
   语义。没有跨键结果缓存，也没有异步菜单刷新。

本例「外婆 + 20 个三字候选」实际统计：Transformer 节点 **120→33**，
全词表预测行 **60→31**。不是把候选数减成 5，也不是少算末字概率。

## 性能与边界

原实现是本轮开始时保存的已修复正确性版本；不使用修复前被错误门控旁路的
版本作为速度基线。两版均保留原模型、候选与评分目标，按 `-O2` 构建。

### 固定真实候选批次，纯神经评分

两个持久 probe 进程交替执行，每个 3 次预热、21 次测量，没有并发推理：

| 版本 | P50 | P95 | 首次进程请求 |
|---|---:|---:|---:|
| 原实现 | 32.572ms | 41.033ms | 46.141ms |
| 优化实现 | 12.085ms | 19.004ms | 21.107ms |

这轮各候选原始对数分最大绝对差约 **5.73e-6**，首选仍是「嫁给了」。
这些首次值不等于磁盘冷启动；未清理系统缓存，未停止用户后台应用。

### 同一隔离 Rime 目录，真实逐键输入

分别启动进程，一次上屏「外婆」，反复输入 `jwgzle` 后 Escape，不提交目标。
首轮计入 cold，另丢弃 3 次预热，再测 31 次；所有最终菜单首选均为「嫁给了」。
计时包含 `process_key` 与菜单读取，不包括屏幕实际绘制。

| 版本 | 热态 P50 | 热态 P95 |
|---|---:|---:|
| 原实现 | 35.911ms | 43.414ms |
| 优化实现复测 | **15.610ms** | **16.260ms** |

原始结果：`/tmp/mohu-neural-opt-20260908/e2e-baseline.json`、
`e2e-optimized-repeat.json`。优化版更早一轮热态 P50/P95 为 15.416/24.256ms，
保存在 `e2e-optimized.json`，不因尾延迟较高而删除。

**冷启动仍未解决：**新隔离副本首次运行观察到优化版 186.459ms、随后基线版
181.229ms 的首次末键；同目录后续新进程的优化版首次为 22.192ms。这些不是
受控的磁盘冷态配对，不能据此宣称 cold P95，也不能用 22ms 掩盖曾出现的
180ms 级停顿。最终重新构建后的三次独立会话正确性验收也全部首选「嫁给了」，
末键为237.544/22.941/23.001ms（`final-e2e.json`）；第一轮再次出现更高的冷态
停顿，不能隐去或算进热态优化成果。当前优化主要解决热态计算，不提供最坏
按键延迟保证，因此本轮不替换线上输入法运行库。

### 剩余热点

仅在 scratch 头文件插桩，24 次请求剔除前三次后，优化版阶段平均值：

| 阶段 | 平均耗时 |
|---|---:|
| Transformer 线性 GEMM | 8.627ms |
| GELU | 0.505ms |
| LayerNorm | 0.600ms |
| 注意力 | 0.197ms |
| 词表输出 GEMM | 1.272ms |
| 全词表 logsumexp 与回填 | 0.359ms |

此轮纯推理 P50 为 11.771ms。GELU/重复注意力成本大幅下降，但线性 GEMM
没有随节点数同比下降，已经成为主要瓶颈。矩阵形状、权重访问和库内实现可能
影响收益，本次未进一步拆分这几项，不把全部成本归因于内存带宽或某个 BLAS
内部行为。**完整末键仍未达到 10ms。**后续应另行评估矩阵后端、权重布局、
量化或更小模型，不能用缓存命中的旧输入掩饰新输入开销。

## 上下文窗口实验

使用 `frozen_v1.jsonl` 的 9,600 条本地语料，按上下文长度分桶，确定性选取
200 个有同码词竞争的句尾案例，全部为真实词表候选组（每组2–4项），没有
合成补位、OOV 排除或最高分并列。另加入实际20候选与混合长度/OOV压力用例，
共202个案例。每个窗口与实现都先预热一遍，再轮换顺序测3遍，共8,082次请求。

**这是离线诊断，不是训练集去重后的正式质量基准。**自然语料的最长上下文为
37字，不能代表160字长文表现；小候选池结果也不能当成20候选末键延迟。
表中时间为每例3次测量的中位数，再对200例取P50/P95，不是屏幕响应时间。

| 窗口上限 | 正确首选/200 | 正确率 | 优化版纯推理P50 | P95 | 相对160字修坏/修好 |
|---|---:|---:|---:|---:|---:|
| 2 | 168 | 84.0% | 10.354ms | 10.646ms | 20 / 5 |
| 4 | 179 | 89.5% | 10.529ms | 10.724ms | 7 / 3 |
| 8 | 180 | 90.0% | 10.653ms | 10.980ms | 4 / 1 |
| 16 | 184 | 92.0% | 10.762ms | 11.071ms | 0 / 1 |
| 160（默认） | 183 | 91.5% | 10.791ms | 12.831ms | 0 / 0 |

两字上限比默认P50只少约0.44ms，却净损失15个正确案例。比如「请求朝廷差官」
之后，本来首选「仲裁」，只留末两字后改为「种菜」。8字窗口也会损失消歧信息：
「现在案件最大的问题就是能不能串」之后，「并案」被「病案」替代。

因此**不默认裁成2/4/8字**。16字在本小样本中没有修坏，可作为显式试用档，
但只有37字以内的200例不足以证明全场景无损，源码默认保持160。共享上下文
以后，短窗口不再是解决热态延迟的主要手段。

所有窗口下优化前后的同输入评分共 **3,030对**：绝对误差最大 **1.907e-5**，
低于 `1e-4` 验收阈值，首选集合与全部候选排名 **零不一致**。实际20候选各档
都仍是33个节点/31个输出行、首选「嫁给了」，因为其真实上下文本来只有两字。
其纯推理中位数约11.93–12.11ms，不会因上限从160改成8而减少有效输入。

原始资产与逐例结果位于 `/tmp/mohu-neural-opt-20260908/context-benchmark/`：
`manifest.json`（输入/二进制/脚本SHA256、方法与限制）、`cases.jsonl`、
`rows.jsonl`、`case_results.jsonl`、`comparisons.jsonl`、`summary.json`。

```sh
python3 research/lm_sentence_compare/neural_context_benchmark.py \
  --probe /tmp/mohu-neural-opt-20260908/probe \
  --baseline-probe /tmp/mohu-neural-opt-20260908/baseline/probe \
  --model "$HOME/Library/Rime/mohu/neural_v3.bin" \
  --vocab "$HOME/Library/Rime/mohu/neural_vocab.json" \
  --lexicon tiger_sentence_native/data/zrm/mohu_zrm.lexicon.txt \
  --corpus research/lm_sentence_compare/corpus/testset/frozen_v1.jsonl \
  --output /tmp/mohu-neural-context-new-run --limit 200 --repeats 3 --warmups 1
```

输出目录必须不存在或为空，避免覆盖旧报告。构建与聚合工具有11项单元测试，
包含持久假probe、确定性分桶、并列排除、顺序轮换、超时和异常数据检查。

## 回归与数值验证

- 短串：从原 packed scorer 捕获确定性小模型 golden，绝对误差阈值 `2e-5`。
- 最大长度：160 字有效上下文、216 个 31 字候选，6,251 节点；原实现 golden
  分数阈值 `1e-4`。复核观察到约 `2.29e-5` 的累积浮点差异、无排序反转，
  不把长串也描述为已经通过 `2e-5` 的界限。
- 结构测试覆盖同文去重、候选重排/单独评分一致性、混合长度导致的不同上下文
  截断、空/OOV、上下文配置先于加载、160 码点硬上限、无用末字消除、跨输出
  tile 的回填、大树有界注意力。失败的词表重载清零本次统计，不沿用旧计数。
- 向量算子测试：253,587 个 GELU 样本、1,696 个 logsumexp 案例；GELU 对原
  标量实现最大绝对误差 `4.77e-7`，测试中的 logsumexp float 返回与原实现一致。
- 新增 C/Lua 上下文接口验证；Lua 配置测试 155 项。真实模型直接 C ABI 核验
  2 字上限等于原完整接口传入相同两字后缀，0 字上限在不同非空上文下结果相同。
- 原生安全、Lua 安全、用户模型、读音先验、上下文、神经重排、词级评分通过；
  词级评分中可选 v6 merged 容器资产缺失的分支仍明确 skip。
- 12 个相关 Lua 测试文件通过；不运行会大规模重写既有词典的 `make all/test`。
  全局 `git diff --check` 的旧 flypy 词表尾空格属于本轮开始前已有改动，不修改。
