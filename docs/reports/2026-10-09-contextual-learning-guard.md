# 个人学习的上下文守卫

日期：2026-10-09。基线源版本：e3900d9。适用：魔虎自然码/小鹤主方案，macOS runtime 本机验证；Windows 需重新编译 runtime 才启用 native 新能力。

## 问题与隔离结果

用户报告“编辑”先上屏，再输入 mabc 首选马标；反例要求整句费尽千辛万苦不能为了提高词频而改成费劲。

这不是单一词频问题。静态字符模型见过“编辑马”，未见跨边界三元“辑马标/辑马表”；前文后的稀疏匹配可退到通用字符/词内概率。个人 trigram 的二元/单字回退、独立词的 BOS/EOS 统计与内部个人词边进一步泛化到新语境。最初只关个人模型但保留个人词库的实验不能隔离全部学习渠道。去掉两层，真实完整菜单可输出编辑码表、费尽千辛万苦；恢复个人模型可翻转。

## 修复

- 新增 tiger/learning_context_guard，两主 schema 默认开启。C ABI 默认 legacy，Lua 明确设置；已有快照和 userdb 格式不变，不删除数据、不提高字词频率。
- 用户字符层仅在实际观察到当前两字上下文时融合精确三元概率；未观察的新语境不借用单字/二元回退作为个人证据。
- 长句组合路径的独立词 BOS 加分不外溢，组合 EOS 使用静态分；整段命中的个人词/短语仍有完整学习通道。
- 静态已有词（含 rank99 注入词）的内部个人边只在真实个人跨边界三元支持时加分；新造词保持内部 boost。未付加分的静态词边不把所有组合兄弟标成个人候选，避免绕过 3/4 字菜单的词库围栏。
- native 字符评分保持原第一返回表，并额外给出“前文末字＋候选前两字”的真实静态/个人三元支持。默认 word-order 保留首位基线，只允许有支持的次选参与越位；旧 runtime 的 nil 元信息保持兼容；畸形元信息整批直通。
- whole-input 变成内部边时重新解码，包括个人词与单字；完整协议的增量/全量一致性有回归测试。共享引擎拒绝相反 guard 设置，避免 Lua 和 native 开关不一致。
- 连续提交发现已有刷新错误：个人扫描 state 已改为归并 acc/order，但事务交接仍读取 state.parts，产生 nil 错误并停在刷新阶段。交接改为 scan_finish 后拆分完整行，保留归并提交计数。新增独立 Lua 回归。

直接减去 BOS 基线的 lift 方案在旧七变体大样本上退化，本次没有采用。没有硬编码码表/马标或费尽/费劲，也不回改已上屏文字。
