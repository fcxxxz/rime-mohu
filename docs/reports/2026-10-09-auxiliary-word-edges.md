# 辅码完整词匹配与 V5 词边界保护

日期：2026-10-09。用户授权自主实现、验证、本机覆盖，并通过 home_nas QQ 提醒。

## 用户问题与最终采用的方案

原本 `vgxjuvijxwudi` 首选整句直接无敌，`xmzlvgxjuvijxwudi` 首选现在整剧直接无敌。
V5 逐字打分使 ju 的条件从句首+整变为在+整，且带辅的 vgxju 找不到 vgju 的
整句词边。此次保持 V5，补回合法辅码词的身份，并限制缺乏直接搭配记录的
跨词字符回退对已确认完整词的影响。

没有修改码表、词频或模型文件，也没有写针对整句/现在的强制替换。

## “现在+整”的真实词级对照

用现有 kn4 独立词评分器，解析后窗口确实是 [现在][整]：

| 窗口 | 句 | 剧 | 车 | 局 |
|---|---:|---:|---:|---:|
| [BOS][整] | -7.300621 | -6.988804 | -5.622780 | -11.491379 |
| [现在][整] | -7.836992 | -8.591717 | -6.415090 | -8.721907 |
| [输入法][整] | -7.836992 | -8.591717 | -6.415090 | -8.721907 |

现在+整能翻正句/剧，但没有直接的 [现在][整] 三元记录，实际回退到整→候选的
词二元统计；输入法+整相同。词表中车的字面概率还高于句，仍需读音约束。
因此不能宣称旧模型理解了“现在”的语义，也不能用这个局部结果证明它适合
整体替换 V5（旧词模型先前还把编辑码表选成编辑嘛表）。

默认运行仍是 V5 字符模型。此次词证据融合是在 V5 上保护完整词，**没有把
默认模型改成真正的词三元模型，也没有声称字窗口变成了两个完整词**。
此前主模型为 MHKNM01 时的两个完整词播种修复继续保留。

## 辅码匹配结构和正确性边界

加载期从现有可作内部边的静态全码词建立规范音节+汉字 trie；引用原词条的
编码和行号，避免复制全表。字符飞键读音通过已有 reading_key 归并。
当前自然码数据：45144 条源词，47024 个节点，47023 条转移；结构容量估算
5932753 字节，约 5.66 MiB，不含分配器额外开销。

逐次输入先在 beam 外解析真实单字码行，包括辅码和选重键。词匹配沿 trie
走这些已验证的音节/汉字转移，每个输入起点只算一次，所有 beam 路径复用。
不逐候选扫描词表，不在字典中生成辅码组合，不通过盲删字符“归一化”。

- 首辅、末辅、多位置辅码、飞键可识别为原完整词，保留实际 preedit 辅码。
- 不匹配的辅码和读音不通过；ju 的车不能借用 vgie 的整车词条。
- 注入 rank >= 90 词仍按原策略排除内部边，简词仍受原开关约束。
- 显式已存在的词编码优先，派生结果按输入终点/文本去重。
- 若只有偶数长度辅码，而整个片段也能完整解释为普通两键单字音节，保持
  原路径竞争、不引入新的派生词票。例如 dewo 可以是得+我，不能为了得的
  两位辅码而把我吞掉。此保守边界意味着并非每种双辅歧义串都新增词边。
- 个人覆盖刷新不重建静态 trie；引用来源行和编码，读取当下覆盖字段。

同时修复数字选重解析漏读首个数字的问题，明确回归 2/0/12。

## 有上限的词边界保护

仅针对合法匹配的派生辅码词，在前缀尾部存在词典二字词时考虑保护。
只有跨词字符三元没有直接记录、个人层没有真实该搭配、而本词内部有直接
句首三元记录时，才加入一部分内部证据：

```text
补分 = min(1, weight × max(0, min(2, 本词内部静态分 − 跨词静态分)))
默认 weight = 0.5
```

每条路径最多用一次，整条路径最多一 nat。已有真实上下文和个人搭配不覆盖；
缺少本词证据也不保护。曾用/未用这笔预算的同文本保留为不同 beam 状态，
最终输出按文本合并、质量取最佳路径、概率质量正确汇总，避免重复候选。
前词的识别由文本词证据决定，同文的不同字符/词切分不会任意丢掉前词身份。

完整补字图的最大消费长度和内部选重键也计入增量重算范围。追加、删字与
完整重算保持一致。

可选排障开关（平时不用改）：

```yaml
patch:
  tiger/auxiliary_word_edges: false       # 关闭新词边
  tiger/auxiliary_context_guard: 0        # 只关闭词边界保护
```

对应 C/Lua API 均有范围校验；桥接旧动态库时继续正常工作。
